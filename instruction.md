# Bucketwatch object-routing rollup — deployment recovery

The Bucketwatch object-routing rollup went down after a failed deployment, leaving both the host deployment state and the rollup compiler wrong. There are three independent deliverables, in any order.

**Deployment state.** Restore the host to the state defined in `/app/docs/deployment_runbook.md`: the `svc-objship` service account, the `/usr/local/bin/ship-objects` wrapper (lock-aware, exit `75`), the cron drop-in, `/app/output` and `/var/log/object-ship` ownership and modes, the logrotate drop-in, and removal of the crashed run's stale lock and unrotated leftover. The runbook gives every name, path, mode and exact line.

**Rollup pipeline.** Repair `/app/workflow/export_report.py` so it turns the telemetry at `/app/data/events.json` into `summary.json`, `bucket_matrix.json`, and the compact JSON-lines `escalated.jsonl` under the output directory. Leave the frozen snapshot `/app/workflow/.export_report.original` unmodified. Acceptance is behavioural: deterministic across reruns and correct on an unseen event stream.

**Audit CLI.** Build `/app/object_audit.py`. `diagnose --dossier PATH --report PATH` writes a stateless report of the six defects to `--report` (omitting `verified_summary` and `output_paths`); it accepts only those two flags and exits non-zero, writing no report, on any other. `repair --output-dir PATH` (default `/app/output`) rebuilds the pipeline from the frozen snapshot, reruns it, and writes `diagnosis.json` and `repair_audit.json` beside the three files.

Every governing value — normalization, `object_id` dedupe tie-breaks, override windows, the near and wide probes, chain correlation and reach, the chain-influence fixed point, and the escalation ledger — lives only in the dossier `/app/incident/export_dossier.md`, where a later dated ruling supersedes an earlier one. The exact schemas, key sets, digest payloads, checksum serialization and the per-issue evidence rules are pinned in `/app/docs/report_spec.json` (with `/app/docs/output_contract.md` as the guide): each `dossier_quote` is a verbatim dossier substring, and every evidence field must contain the terms listed per issue id under `required_terms_by_issue`.
